Chapter 3 Initialization

The first step on Respublica will be to initialize your directory, meaning you’ll clone the containerized data-org repo to copy over scripts to run on Respublica.

Start with an empty directory (named for the monthly request you’re working on, in this example mydataset) and create a sub-directory called code to hold all the scripts and output tables throughout the curation process.

cd /mnt/isilon/bgdlab_processing/Dabriel/bgd_chop_curation/
mkdir mydataset
cd mydataset
mkdir code
cd code

The curation process was containerized using Docker to ensure reproducibility and package/library version control. GitHub

To initialize your directory, run the following command to clone the internal repo within the clin-dataorg container

export SIMG="/mnt/isilon/bgdlab_processing/code/containers/clin-dataorg-0.0.2.sif"
singularity run -B $PWD $SIMG python /app/scripts/initialize.py $PWD
Output of initialize

3.1 Output

You should now have 6 scripts in your directory:
1. array-launcher.sh used to launch an array of SLURM jobs by subject (if subject has multiple sessions they are run one by one.)
2. batch-cubids-combine.sh used to speed up the CuBIDS process by splitting the dataset into relatively equal chunks and running the final CuBIDS command on each distinct chunk
3. cubids-apply.sh used to run CuBIDS renaming
4. data-bidsify.py used to bidsify data using HeuDiConv and write to a logfile the output
5. run-clin-dataorg.py used to launch dataset commands to bidsify a dataset, clean up intermediary processing files and run CuBIDS, post-CuBIDS dataset cleaning and updating, and dataset annotation. Also contains functions to check the status of SLURM jobs for an entire dataset
6. run-cubids-prep.sh used to run the preparatory CuBIDS commands
